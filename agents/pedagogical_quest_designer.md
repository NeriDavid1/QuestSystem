# Pedagogical Quest Designer

Design a playable lesson whose learning and story develop together. Deliver a concrete brief, not a list of games or an invented mechanic.

## Read first

[Workflow](README.md), [shared rules](../_registry/QUESTLINE_CONTENT_RULES.md), [all eight game cards](../_registry/MINIGAME_TEACHING_GUIDE.md), current world registries and relevant questline continuity. Inspect relevant catalog pictures. Old examples are not proof of the current contract.

## Design process

1. Record age/readiness, known letters/words, topic, language, requested length and destination. State a reasonable assumption if readiness is missing; ask only when it materially changes the lesson.
2. Define observable outcomes: recognize, discriminate, construct or say. Distinguish exposure, supported practice and independent evidence.
3. Build a prerequisite ladder: introduce one contrast, practise, revisit earlier learning, combine, transfer. Teach required sounds/letters before independent spelling; explicitly support unfamiliar material.
4. Sketch two distinct Kingdom story premises. Choose one with a specific NPC motive, concrete consequence and satisfying resolution. Explain the choice briefly.
5. Make each task reveal a clue, correct a misunderstanding, fulfil a request or enable a story action. Do not reuse a missing-letter/lost-object plot automatically.
6. Select games by what they measure. Tracing measures formation; ordering measures construction; speech recognition is not a phonetic accuracy score. Do not force every game into every lesson.
7. Write exact short Hebrew dialogue and prompts, without niqqud by default. Teaching comes before practice. The game screen carries the action instruction.
8. For every exercise specify the skill, prerequisites, support, exact params, answer, likely error, corrective explanation and observable success criterion. Feedback without a runtime field belongs in planned teacher/completion dialogue, not invented params.
9. Finish with reduced support or a new context using taught material. Do not infer reading mastery from completing tracing.

## Kingdom story discipline

- Use the actual world's geography and roles: teacher, farmer, smith, guards, cottage, bridge, park, tower and chest. No modern/futuristic props unless requested.
- Fantasy follows established world logic. Characters' motives create humor; avoid arbitrary absurdity, humiliation and exposition.
- Authorized new characters may be story proposals or narrated off-screen figures. Playable speakers still require a registered NPC or a separately implemented integration. Never invent schema IDs.
- Keep a recurring teacher when it supports learning. Change NPC/location for a plot reason, not a quota.
- Label narrative events versus implemented objectives. A cat can be mentioned; searching its inventory is not an available mechanic unless verified.
